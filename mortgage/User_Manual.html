住宅ローン試算・審査状況比較シミュレーター：顧客向け操作マニュアル

1. はじめに

本マニュアルは、お客様の年収・年齢条件に基づき、複数の金融機関における住宅ローンの金利、返済期間、月々返済額、および審査適合性を一括でシミュレーション・比較するためのWebアプリケーションの操作手順を解説するものです。

2. 画面構成と基本操作

① お客様基本条件設定エリア

画面上部の「お客様基本条件設定」カードにて、以下のベース条件を入力・変更します。数値の変更はリアルタイムに下部の比較テーブルへ反映されます。

  • ご年収 (額面): 額面の年収を万円単位で入力します。
  • 借入希望額: ご希望の借入金額を万円単位で入力します。
  • 年齢 (実行時): ローン実行時のご年齢（歳）を入力します。完済時年齢や返済期間の自動計算の基準となります。
  • 表示フィルター: すべての金融機関を表示するか、「提携」ローン、「非提携」ローン（プロパー）のみに絞り込むかを選択できます。

② 金融機関別 返済・審査比較一覧テーブル

複数の金融機関の条件が一覧化されています。各列の主な機能は以下の通りです。

  • 金融機関名 / 種別: 提携・非提携の種別や銀行名を確認・変更できます。
  • 金利関連項目（基準金利・優遇金利・上乗せ金利・適用金利）: 小数点以下3桁まで正確に表示・入力されます。適用金利は 基準金利 － 優遇金利 ＋ 上乗せ金利 で自動計算されます。
  • 返済期間 / 完済時年齢: 「年齢（実行時）」と金融機関の「最大期間」から逆算された最適な返済期間が自動入力されます。必要に応じて手動での変更も可能です。
  • 月々返済額: 借入希望額、適用金利、返済期間を基に算出した毎月の返済額（元利均等返済方式）が表示されます。
  • 審査取扱いステータス: ご年収に対する返済比率と各行の「返済率上限」を照らし合わせ、「審査可能」「審査未定」「審査不可」が自動判定されます（手動変更も可能）。
  • テーブルのカスタマイズ:
  • 列の並び替え: ヘッダーをドラッグ＆ドロップすることで、列の順序を自由に変更できます。
  • 列幅の調整: ヘッダーの右端をマウスでドラッグして幅を調整できます。
  • 行の並び替え・追加・削除: 行のドラッグによる並び替えや、「金融機関を追加」ボタンによる新規行追加、不要な行の削除が可能です。

③ 一般閲覧モード（審査項目非表示機能）

  • 画面右上の「一般閲覧モード（審査項目非表示）」ボタンをクリックすると、お客様へ提示する際に非表示にしたい審査金利や審査用期間、審査比率などの機密・内部審査項目を一括で非表示に切り替えることができます。

3. データの保存・読込・初期化

  • JSON保存: 現在の入力内容やカスタマイズしたテーブル設定をJSONファイルとしてダウンロードできます。物件名・お客様名・作成日（CV町屋_○○様_2026-11-03）等、適当な名前で保存してください。
  • JSON読込: 以前保存したJSONファイルをアップロードすることで、前回のシミュレーション状態（お客様内容、金利、表示順番など）を復元できます。
  • 初期化: 「初期化」ボタンを押すことで、初期状態のデータにリセットできます。
  • ブラウザ自動保存: 入力したデータはブラウザ（localStorage）に常時自動保存されるため、ページを再読み込みしても内容が保持されます。

4. 印刷・PDF出力機能

  • 画面右上の「A3印刷・PDF出力」ボタンをクリックすると、A3横サイズの印刷プレビューが起動します。
  • お客様への提案資料として、上部の「一般閲覧モード」を押していただくと、最適なレイアウト（余白の最適化、不要なUIボタンの非表示、フッターの著作権表示等）で綺麗に出力・PDF化が可能です。

5. よくあるご質問（Q&A） - 顧客向け

Q1. 入力した数値が変わると返済額はすぐに再計算されますか？

  • A: はい。年収、借入希望額、年齢、各金利、返済期間などの数値を変更すると、デバウンスやリアクティブバインディングにより即座に月々返済額および審査比率が再計算されます。

Q2. 「一般閲覧モード」にすると、どの項目が隠れますか？

  • A: 審査金利、審査用返済期間、審査返済率、返済率上限、審査条件、審査取扱いステータス、備考などの内部審査用カラムがすべて非表示となり、お客様への分かりやすい返済額・金利比較表としてスッキリ表示されます。

Q3. 年齢を変えると「返済期間」はどうなりますか？

  • A: 各金融機関が定める「最大期間」と、「完済時年齢（デフォルト80歳等） － 実行時年齢」を比較し、より短い（安全な）期間が自動的に返済期間として設定されます。もちろん手動で短く変更することも可能です。

Q4. 画面を閉じたりブラウザを更新したりしても、入力したデータは消えませんか？

  • A: 消えません。ブラウザのローカルストレージに自動保存されているため、次回のアクセス時にも直前の状態から作業を継続できます。

Q5. 独自の金融機関を追加してシミュレーションすることはできますか？

  • A: はい可能です。テーブル上部の「金融機関を追加」ボタンをクリックすることで、任意の金融機関行が追加され、金利や特約、メモなどを自由に入力できます。

Q6. A3印刷時にボタンや不要なメニューが印刷されて見づらくなることはありませんか？

  • A: ございません。印刷用の専用CSSメディアクエリ（@media print）を実装しているため、操作ボタンやヘッダーのナビゲーションなどは自動的に非表示になり、A3横サイズに最適化された表形式で印刷・PDF出力されます。※A4横サイズにする場合は、印刷時にA3⇒A4に縮小してください。

住宅ローン試算・審査状況比較シミュレーター：システム設計書（管理者・エンジニア向け）

1. システム概要

本システムは、クライアントサイド（ブラウザ）完結型のシングルページアプリケーション（SPA）です。Node.jsやNext.jsなどを使用していないため、外部サーバーへのDB通信を伴わず、Vue.js 3のリアクティブ機構を利用して動的な住宅ローン金利計算、返済シミュレーション、および金融機関別の審査判定を高速に実行しています。 Writen by S.Hirai

2. 技術スタック

  • プログラミング言語: HTML5,CSS3,Javascript (ECMAScript), JSON: Ver:4.0-vue
  • 開発ツール・周辺環境: Visual Studio Code(Ver:1.144),Git/GitHub
  • フロントエンドフレームワーク: Vue.js 3 (Composition API / CDN版)
  • スタイリング: Tailwind CSS (CDN版)
  • アイコンライブラリ: Lucide Icons
  • データ永続化: HTML5 Web Storage API (localStorage)
  • ファイル入出力: Native File API (JSON Export/Import)
  • 印刷対応: CSS Paged Media / A3 Landscape Print Media Queries

5. UI/UX仕様・レスポンシブ・印刷制御

  • Sticky Header: 横スクロール時、第1列の「金融機関名」が常時左側に固定される (position: sticky)。
  • ドラッグ＆ドロップ: HTML5 Drag and Drop API を用いて、テーブルヘッダー（列順入替）および行（金融機関の並び順入替）の直感的な並び替えを実現。
  • 列幅リサイズ: マウスイベント（mousedown, mousemove, mouseup）を監視し、各列のピクセル幅を動的に可変調整可能。
  • 印刷スタイル最適化: @media print により、A3横サイズ（size: A3 landscape）を指定。不要な操作ボタン等を非表示にし、顧客条件セクションのフォントサイズを拡大して視認性を確保。

6. 保守・拡張性に関する留意事項

  • ストレージキーのバージョニング: データ構造変更時は STORAGE_KEY_DATA 等のサフィックス（例: _v15）をインクリメントし、古いスキーマとの衝突を防ぐこと。
  • 初期データフォールバック: ローカルストレージにデータが存在しない場合、外部URL (vladesite.github.io) からのJSON取得を試み、失敗した場合はハードコードされた initialBankData にフォールバックする堅牢な設計となっている。

7. よくあるご質問（Q&A） - 管理者・エンジニア向け

Q1. 金利データの入力値が小数点以下3桁に強制丸めされるのはなぜですか？

  • A: 金融機関の金利提示において0.001%単位の精度（例: 3.375%、役務特約や優遇幅の正確な計算）が不可欠であるため、formatRate 関数および toFixed(3) をバインディング層および計算層で強制適用しているためです。

Q2. ユーザがブラウザのキャッシュをクリアした場合、保存したカスタムデータはどうなりますか？

  • A: 本システムはサーバーサイドDBを持たず、ブラウザの localStorage に依存しているため、キャッシュやストレージをクリアすると初期データにリセットされます。重要なカスタム状態は適宜「JSON保存」機能を用いてファイルとしてバックアップすることを推奨します。

Q3. 「返済期間」と「審査用返済期間」の連動仕様はどうなっていますか？

  • A: デフォルトでは「返済期間」の値が「審査用返済期間」にも同期して適用されますが、個別の金融機関で審査上の制限やストレステスト用期間が異なるケースに対応するため、手動で「審査用返済期間」を上書き変更できる個別オーバーライド機構を持たせています。

Q4. 一般閲覧モード切り替え時のDOM制御はどのように行われていますか？

  • A: Vue.jsのリアクティブ変数 isExamColumnsHidden を監視し、対象となる <th> および <td> 要素に対して動的に .col-hidden クラス（display: none !important）を付与・解除することで、DOMの破棄を伴わずに高速な表示切り替えを実現しています。

Q5. 印刷時にA3横サイズ以外のレイアウト（A4等）で崩れるリスクはありますか？

  • A: 本システムは情報量が多いため、印刷スタイルシートで @page { size: A3 landscape; } を厳格に指定しています。A4等で印刷した場合、テーブルの列数（19列）が多く自動縮小されるため、必ずA3プリンターまたはPDF出力時の用紙サイズ「A3」の指定を徹底してください。

Q6. 新規の金融機関行を追加した際の一意なIDの生成方式は何ですか？

  • A: addRow() メソッド実行時に Date.now().toString() を用いてタイムスタンプベースの一意な文字列IDを生成し、Vueのリアクティブ配列に追加することで、V-forレンダリング時のキー衝突やDOMの誤描画を防止しています。
