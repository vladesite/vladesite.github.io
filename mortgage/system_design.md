# 住宅ローン返済額 ＆ NISA資産運用シミュレーター システム設計書

## 1. システム概要

本システムは、住宅ローンの長期返済（35年〜50年）とNISA積立投資を組み合わせた「資産運用型住宅ローン計画」をリアルタイムでシミュレーション・可視化する1ファイル構成のWebアプリケーションです。

* **ファイル名**: `mortgage.html`
* **動作環境**: モダンブラウザ（Chrome, Edge, Safari, Firefox等）
* **設計形態**: クライアントサイド完結型SPA（サーバーレス / 1ファイル・マニフェスト）

## 3. アーキテクチャと処理フロー

本アプリケーションは外部バックエンドAPIを使用せず、すべてブラウザのJavaScriptエンジン内で即時に計算およびDOM/Chart更新を行います。

```
[ ユーザー入力 (Form / Slider) ]
             │
             ▼
[ イベントハンドラ (input / change) ]
             │
             ▼
[ 数値バリデーション ＆ 入力相互同期 (setupSync) ]
             │
             ▼
[ 計算ロジック実行 (updateAllCalculations) ]
 ├── ① 住宅ローン毎月返済額算出 (calcPMT)
 ├── ② 残債額算出 (calcLoanBalance)
 ├── ③ NISA積立複利計算 (calcInvestmentFV)
 └── ④ 最短逆転（実質完済）月数の探索ループ
             │
             ▼
[ UI ＆ チャート更新 ]
 ├── DOMテキスト書き換え (サマリーカード / テーブル)
 └── Chart.js インスタンス更新 (renderChart)
```

## 4. 主要計算ロジック仕様

### 4.1. 毎月返済額（PMT）の計算 (`calcPMT`)
元利均等返済の公式に基づき、毎月の返済額（円単位、四捨五入）を算出します。

$$
PMT = P \times \frac{r(1+r)^n}{(1+r)^n - 1}
$$

* $P$: 借入金（円）
* $r$: 月利 ($\text{年利(\%)} / 100 / 12$)
* $n$: 総返済月数 ($\text{返済年数} \times 12$)

### 4.2. 指定月経過後のローン残債計算 (`calcLoanBalance`)
経過月数 $m$ 時点でのローン残債（万円単位、切り捨て/四捨五入）を算出します。

$$
Balance(m) = P \times \frac{(1+r)^n - (1+r)^m}{(1+r)^n - 1}
$$

* $m$: 経過月数 ($\text{経過年数} \times 12$)

### 4.3. 差額積立複利運用の将来価値計算 (`calcInvestmentFV`)
毎月の節約額（35年返済額 - 長期ローン返済額）を年利 $R$ で毎月積立運用した場合の資産額 $FV$ を算出します。

$$
FV(m) = S \times \frac{(1+r_i)^m - 1}{r_i}
$$

* $S$: 毎月積立額（35年ローン月額 - 選択ローン月額）
* $r_i$: 運用月利 ($\text{想定運用年利(\%)} / 100 / 12$)
* $m$: 経過月数

### 4.4. 最速実質完済月の特定処理
1ヶ月目から選択ローンの総月数 ($n$) までループを行い、$FV(m) \ge Balance(m)$ となる最小の月数 $m$ を探索します。

## 5. UI / デザイン仕様

* **ダークモード基調（画面表示時）**: Deep Navy (`#0b1324`) を背景とし、Cyan (`#06b6d4`), Emerald (`#10b981`), Amber (`#fbbf24`) のアクセントカラーで近未来的かつ視認性の高いグラスモーフィズムデザインを採用。
* **印刷最適化（`@media print`）**:
  * 印刷用CSSスタイルを定義し、背景を白色 (`#ffffff`)、文字色を濃紺・黒色 (`#0f172a`) へ自動反転。
  * チャート軸やグリッド線も印刷用に暗色化。
  * `.no-print` クラスを付与した要素（印刷ボタン、初期化ボタンなど）は非表示化。

---

## 6. 保守・拡張時の注意事項

1. **JavaScriptのスコープ管理**:
   * 全処理が即時実行関数（IIFE）内にカプセル化されており、グローバル汚染を防ぐ設計になっています。
2. **Chart.js のリビルド**:
   * 再計算時は `chartInstance.update()` を使用して再描画パフォーマンスを維持しています。データ構造を変更する場合は `renderChart` 関数内を更新してください。
3. **入出力相互補正**:
   * 自己資金が物件価格を超えないよう `setupSync` 内でガ動的ガードが施されています。入力制御の仕様変更時はこのロジックを確認してください。
